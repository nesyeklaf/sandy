## Probe stage result -> design impact (SANDY 0.47.1, 2026-10-27)
Evidence: /tmp/sandy-delegate-probe/RESULTS.md. Restore: /tmp/sandy-delegate-probe/restore.log (plugin removed, ext removed, 24 [probe] threads archived, settings diff vs baseline = 0 keys, idle timeout 30).
Verdict: no load-bearing assumption refuted -> go to spec with these adjustments to synthesis.md:
1. Depth: SANDY allows grandchildren (P11). sandy_delegate refuses when the caller thread is itself a delegate.
2. Archive: archiving a parent archives all children via parentThreadId (P17). lifecycleOwnerThreadId not needed for cleanup; parent stop leaves children running (owner wish holds natively).
3. Wait: plugin tool calls are cut at ~300 s (P2). sandy_delegate wait mode loops in chunks <= 270 s and returns "still running" + id.
4. Enforcement transport: Claude models in this pi reach plugin tools only through codemode. Allowlists must permit codemode as transport; the tool_call gate checks nested calls (P6 proven). Revises synthesis §3.4 point 5.
5. Policy binding: the ext resolves policy through the delegation record (thread id -> plugin), never via title.
6. Questions (corrected after review): requestInput takes timeoutMs (default 10 min, cap 7 days); the plugin sets 7 days (owner). A plugin reload still interrupts a form silently (P8b), so the open question is durable plugin state shown as "braucht dich" in the composer segment; the plugin re-opens the form (outside a tool call) after reload, interrupt, expiry or a click and delivers that answer via threads.send queue-if-active (proven).
7. Status: child status "error" with provider message must show in segment and sandy_delegate_status (a broken global pi ext killed a child start).
8. Sidebar (P12), superseded by the owner after review: sandy-sidebar nests only visible children; hidden delegates and needs-you are not shown there. Reveal = threads.update visibility visible (P16). Owner decision: a narrow sandy-sidebar fork shows hidden delegate children and workers collapsed under their parent with a needs-you marker (SDK ThreadListArgs.includeHidden, sandy-plugin-sdk.d.ts:18216; experimental_listDescendants includeHidden, :18397; thread change events carry hasPendingInteraction); the native thread list stays without them.
9. UI slots (P13): experimental_threadContextSegment, composer banner, experimental_tab with contained ThreadChat via openThreadPanel, pendingInteraction form all render on 0.47.1. Install/update needs a client window reload (README + post-install note).
10. Wake (P1/P15/P10): released parents are woken by child completion and by open questions; steer-if-active reaches a released origin (workflows-plus path ok); parentNotifications off->auto flip works.
11. Multi-host (P14): seraphim (Windows) child has sandy CLI + SANDY_THREAD_ID; host entry must install the pi ext per host.
12. Residual: ack forgeable via sandy CLI (P5), accepted by owner.
